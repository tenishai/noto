# platform-record — the argus-platform-info ConfigMap and tenant resolution

WHAT / SEAM: a ConfigMap named `PLATFORM_INFO_CONFIGMAP = "argus-platform-info"` (agent/argus/rendering/rbac.py:35) in the platform namespace, holding `data: {born, tenant, environment}`. It is the single fact every read command (`observe`, `rules-sync`, `render`) resolves its tenant from, so the tenant a dashboard/rule/report READS with can never silently drift from the tenant the collector gateway WRITES telemetry with. Functions (agent/argus/steps.py): `platform_info_configmap(...)` (the record's shape, preview/golden only — never kubectl-applied wholesale), `read_platform_info` (lenient, never raises, `{}` on any failure), `read_platform_info_strict`/`read_platform_info_required` (raise `PlatformInfoUnreadable` on anything that isn't a clean "absent"), and the `EnsurePlatformInfo` step that writes it.
OPS / FLOW: `EnsurePlatformInfo.apply` first does a STRICT read (`read_platform_info_strict`, or the lenient one under `--dry-run`) — if it fails for any reason other than "record absent", the step refuses to write at all. If the record has no `born` yet, `_create_born` does a `kubectl create` (never a patch) that stamps `born` once; an `AlreadyExists` response is treated as success. `_patch_identity` then merge-patches only `tenant`/`environment`/the managed label — `born` never appears in any write after the create. Read-side: `observe`/`rules-sync` resolve tenant in order — (1) an explicit `--cluster`/`ARGUS_CLUSTER` must agree with the recorded tenant or the run fails before applying anything; (2) otherwise the recorded tenant wins over a disagreeing `gojira.yaml` cluster string; (3) otherwise (no record at all) the contract's own cluster string, with a warning. `render`/`--dry-run` do the same resolution SILENTLY and never require a cluster — an unreadable record there is just treated as a missing one.
INVARIANTS:
- `born` can only ever be set by a `kubectl create` — never overwritten, never appears in a patch. This is structural (create cannot clobber an existing object), not a runtime check, specifically so no failure mode (unreadable pre-read, two runs racing, a hand-deleted ledger row) can move the birth instant, which would mute `ArgusRetentionWindowShort` for a full retention window.
- The WRITE path (`EnsurePlatformInfo.apply`) must use the STRICT read and refuse on anything ambiguous; the READ paths used by `observe`/`rules-sync`/`render` must use the LENIENT read and degrade to a fallback tenant rather than fail a preview or a routine wiring run for want of a cluster.
- `read_platform_info_required` (job mode's read) is distinct from `read_platform_info` precisely because "present but unreadable" in a Job most likely means the job's own RBAC (`render_observe_rbac`'s `Role`/`RoleBinding` granting `get` on this ConfigMap BY NAME) was never rolled out — falling back there would silently wire an app to a tenant nothing writes to and report success.
- `render_observe_rbac` grants `get` only, scoped by `resourceNames: [PLATFORM_INFO_CONFIGMAP]` — no `list`, no other ConfigMap. `steps.py` imports the constant from `rendering/rbac.py` rather than re-typing the string, specifically so a spelling mistake shows up as a permission failure, not silently as a typo.
CONSUMERS: agent/argus/cli.py (`cmd_platform`, `cmd_observe`, `cmd_rules_sync`, `cmd_render` — the tenant-resolution order described above); agent/argus/job.py (job-mode's `ARGUS_CLUSTER` must match the record or the run fails with `tenant mismatch`).
API: no HTTP/RPC surface — this is entirely `kubectl get`/`create`/`patch` against one named ConfigMap, mediated through `StepContext.runner`.
