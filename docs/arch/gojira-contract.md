# gojira-contract — reading gojira.yaml, and the job-mode env-var protocol with a provisioner

WHAT / SEAM: two ways argus learns what app/environment/cluster it is working on, both anchored to gojira's `gojira.yaml` contract shape. Operator mode: `read_gojira_yaml(path) -> GojiraApp` (agent/argus/gojira/reader.py) parses the file directly via pydantic models `GojiraApp`/`GojiraEnvironment` (both `extra="allow"`, unknown fields WARN and are retained — the contract is gojira's and may be newer than this reader). Job mode: `job_inputs(environ) -> JobInputs | None` (agent/argus/job.py) reads the same contract out of `GOJIRA_CONTRACT_YAML`/`GOJIRA_CONTRACT_SHA256` env vars when a provisioner launches `argus observe` as a one-shot Job. Both feed the same downstream (profile resolution, rendering); the job path additionally verifies the contract's integrity and reports a machine-parseable result back via `ARGUS_SUMMARY`.
OPS / FLOW: `job_inputs` returns `None` when `GOJIRA_CONTRACT_YAML` is absent (operator mode — nothing else in this module runs). When present: `contract_fingerprint()` re-derives the sha256 the SAME way the provisioner must (`yaml.safe_load` → `json.dumps(sort_keys=True, separators=(",",":"))` → sha256 of the UTF-8 bytes) and raises `JobInputError` on any mismatch — format (comments, key order, quoting) never affects the fingerprint, only decoded meaning does. `_validate_contract_names` then checks `app`/`namespace` against a strict DNS-1123 LABEL pattern (63 chars, no dots) and `cluster` against a looser pattern (253 chars, dots/underscores/capitals allowed, matching real cloud console names) — BEFORE any temp file is written or any kubectl argv is built, because these strings become object names, namespace names, and tenant headers downstream. `in_cluster_kubeconfig()` writes an explicit kubeconfig (server from `KUBERNETES_SERVICE_HOST`/`_PORT`, token referenced by path so kubelet rotation keeps working) because `--request-timeout` on every argus kubectl call defeats kubectl's own in-cluster-fallback heuristic — this was a real incident (2026-09-25, "platform record unreadable" from a Job silently dialing `localhost:8080`). On exit, `success_summary`/`failure_summary` build the one `ARGUS_SUMMARY <line>` the launcher reads from the pod log tail.
INVARIANTS:
- The fingerprint algorithm in `contract_fingerprint` MUST match the provisioner's (gojira's) byte for byte — this file's docstring states it as a hard requirement, not an implementation detail; changing the canonicalization here without a matching gojira-side change breaks every job-mode run silently (every fingerprint check fails).
- Name validation happens BEFORE the contract's strings are used to build any kubectl argv, temp file, or HTTP path — this is a deliberate boundary check, not defense in depth: `app` becomes a namespace name (label rules, no dots) while `cluster` becomes a tenant header (looser rules), and each gets its own pattern rather than one shared one.
- `job_inputs` requires `ARGUS_ENV` to be exactly one of `dev`/`qa`/`prod` (`_KNOWN_ENVS`) — no other value is accepted, even a syntactically valid string.
- The job ALWAYS ends with exactly one `ARGUS_SUMMARY` line, success or failure — this is what lets a launcher parse a result without scraping the whole log; `summary_line()` collapses to one line and clips to `SUMMARY_MAX` (300 chars) so a pathological error message can never break the one-line contract.
- `read_gojira_yaml`'s pydantic models are `frozen=True` and warn-not-fail on unknown fields — the same forward-compatibility posture as `argus.profiles.models.Override`, because the `observability:` override block travels inside the same gojira.yaml and evolves with gojira's contract, not argus's release cadence.
CONSUMERS: agent/argus/cli.py `cmd_observe`/`cmd_render` (operator-mode file read via `read_gojira_yaml`); `cmd_observe` also calls `job_inputs`/`in_cluster_kubeconfig`/`success_summary`/`failure_summary` when `GOJIRA_CONTRACT_YAML` is set. The provisioner is gojira itself (a separate repo) — it writes the env vars this module reads and reads the `ARGUS_SUMMARY` line this module writes.
API: `read_gojira_yaml(path) -> GojiraApp` (raises `GojiraReadError`). `job_inputs(environ) -> JobInputs | None` (raises `JobInputError`). `contract_fingerprint(text) -> str`. `success_summary(...)`/`failure_summary(...) -> str`. `in_cluster_kubeconfig(dest, environ, sa_dir=None) -> Path | None`.
