# profiles — baseline + class + override → the ResolvedProfile every renderer consumes

WHAT / SEAM: three pydantic model layers (agent/argus/profiles/models.py) merged by `resolve(baseline, cls, override) -> ResolvedProfile` (agent/argus/profiles/resolve.py) into the one frozen shape every renderer in agent/argus/rendering/ is given. `BaselineProfile` (cluster-wide: budgets, drop rules, dashboards, log_collection) and `ClassProfile` (per gojira workload class: signals, slos, dashboards, drop, app_scrape) are OURS — `extra="forbid"`, unknown fields are hard errors. `Override` rides inside `gojira.yaml`'s proposed `observability:` block and is NOT ours — `extra="allow"`, unknown fields warn and are retained (same forward-compat posture as `gojira.reader`). `loader.py` (`load_baseline`/`load_class`/`load_override`) turns YAML files into these models, naming the file and field on any validation failure.
OPS / FLOW: `resolve()` — signals: class's list, plus `traces` appended if `override.traces` is set and not already present. Retention: baseline's dict, `.update()`d by override's (override wins key-by-key). Cardinality: baseline's per-env dict, UNLESS `override.cardinality_budget` is set, in which case every environment is overwritten to that one value. Named collections (`slos`, `dashboards`, `drop`) merge via `_merge_named`: later layers overwrite same-`name` items entirely (no field-level merge), and any item with `enabled: False` is filtered OUT of the resolved list — so disabling an item is done by re-declaring it with the same name and `enabled: false` in a later layer, not by omitting it.
INVARIANTS:
- All models are frozen (`ConfigDict(frozen=True, ...)`) and `resolve()` never mutates an input layer — a `ResolvedProfile` is safe to pass to every renderer without defensive copying.
- `DropRule.raw_ottl` requires a non-empty `justification` (model_validator) — same contract as `Override.cardinality_budget`, which also requires `justification` — both are the "overrides need justification, enforced structurally, not just by review" decision from docs/design.md.
- `SLO.signal == "latency"` requires `latency_threshold` to be set — a latency SLO with no threshold cannot construct.
- `ClassProfile.class_name` is a closed `Literal` over the shipped classes (`web|worker|cron|heavy|gpu|agent|gateway`) — this is also what `_platform_profile()` in cli.py exploits: it constructs a real `ClassProfile` with `class="web"` and empty `signals`, resolves it, then overwrites `class_name` to the synthetic `"platform"` afterward via `model_copy`, because the platform tier is not a workload class and there is deliberately no fake class YAML file for it.
- `app_scrape: bool` (default `True`) suppresses the per-app ServiceMonitor/PodMonitor for classes whose workload contract has no `/metrics` endpoint — the `metrics` SIGNAL stays on regardless (kubeletstats/kube-state-metrics are app-agnostic); this is a scrape-suppression flag, not a signal toggle, and conflating the two is a real way to get this wrong.
CONSUMERS: every module under agent/argus/rendering/ (collectors, alerts, slo, scrape, ottl, perses) takes a `ResolvedProfile` (plus `Context`) as input. agent/argus/cli.py `_resolved()` and `_platform_profile()` are the two call sites that build one, for per-app and platform-tier rendering respectively.
API: `resolve(baseline: BaselineProfile, cls: ClassProfile, override: Override) -> ResolvedProfile`. `load_baseline(path)`, `load_class(path)`, `load_override(dict | None)`.
