# ruler-sync — pushing and pruning PrometheusRule groups against Mimir's ruler

WHAT / SEAM: `PrometheusRule` CRDs are inert in this stack — no Prometheus runs (kube-prometheus-stack is installed only for its operator/CRDs/Alertmanager), so Mimir's ruler is the ONLY thing that evaluates a rule. agent/argus/feedback/ruler.py's `sync_rules`/`list_groups`/`prune_groups` (POST/GET/DELETE against `{mimir_base}/config/v1/rules/{namespace}`, where `mimir_base` already ends in `/prometheus`, tenant header on every call) push rendered groups, list what the ruler holds, and delete stale ones; the `SyncRules` step (agent/argus/steps.py) is the engine step that calls both, in order, for one app's run.
OPS / FLOW: `SyncRules.apply` gets the app's rule-bearing rendered docs (`alerts` + `slo` families, filtered to `kind == "PrometheusRule"`), resolves `(ctx.ruler_url, ctx.ruler_namespace)`, calls `refuse_platform_namespace(namespace)` FIRST (before any network call, even under `--dry-run`), then `sync_rules(...)` (push) and, only if that succeeds, `prune_groups(...)` (delete every group the ruler holds in that namespace that this run did NOT render). `RulerUnreachable` from the push and from the prune are caught SEPARATELY and reported differently: an unreachable push means nothing landed; an unreachable prune means everything this run renders is already in place and only the stale-group cleanup didn't happen — conflating the two would send an operator looking for rules that are actually already live. Whether unreachability fails the run or just degrades to a stderr note is `ctx.ruler_required` (`False` for an operator's laptop, which usually cannot route to the in-cluster URL; `True` in job mode, which runs inside the cluster where nobody is watching stderr).
INVARIANTS:
- Push always happens before prune, and prune only runs if the push succeeded: a failed push must never have already deleted the groups that were working. The ruler module enforces no order itself; the rule is stated in the `SyncRules` class docstring and kept by the callers (`SyncRules.apply` and `cmd_rules_sync` both call `sync_rules` before `prune_groups`).
- `refuse_platform_namespace` guards `PLATFORM_RULE_GROUP = "argus-platform"` specifically: `argus-platform` is a legal app name, and an app that resolved to that ruler namespace would file its groups beside the platform's own retention alarm and then prune it away on its next run (nothing except `argus platform` itself renders that group). The check runs before any HTTP call, in both `SyncRules` and the standalone `argus rules-sync` CLI command, from this one function — "one spelling of the rule."
- Every delete `prune_groups` issues is scoped to the `namespace` it was given — a caller can structurally never reach another app's groups (there is no cross-namespace delete path in this module).
- `SyncRules.check()` only ever returns a skip reason (`"no rules rendered"`) when the app renders NO rules at all; if it renders any, `apply()` always pushes — the ruler's listing endpoint says which groups exist, not whether their contents match, so a POST of an unchanged group is defined as a no-op rather than being pre-filtered client-side. `check()` opens no socket, so `--dry-run` never touches the network here.
- `ephemeral = True` on `SyncRules` (like `ApplyRendered`): the ruler's contents must reconcile every run and are never ledger-skipped, because they can drift out-of-band (a group deleted by hand, an SLO rename).
CONSUMERS: agent/argus/steps.py `SyncRules` (per-app, run by `observe`'s step sequence). agent/argus/cli.py `cmd_platform` (pushes the platform's own `argus-platform` group directly via `sync_rules`, not through the step) and `cmd_rules_sync` (`argus rules-sync`, the standalone re-push-and-re-prune command, resolves tenant/namespace the same way `SyncRules` does).
API: `sync_rules(mimir_base, tenant, namespace, docs, http=...) -> int` (groups pushed). `list_groups(mimir_base, tenant, namespace, http=...) -> list[str]` (group names the ruler holds in that namespace, one GET; `prune_groups` depends on it). `prune_groups(mimir_base, tenant, namespace, keep, http=...) -> list[str]` (groups deleted; `keep` is a set of names). `refuse_platform_namespace(namespace)` (raises `RulerSyncError`). `RulerUnreachable` (raised by the injectable `Http` transport on a genuine connection failure, distinct from a non-2xx HTTP response).
