# noto — repo card

WHAT: the observability arm of gojira. Reads a gojira-managed cluster's deployed apps and their workload class, then stands up an OSS observability platform (OTel Collector + Mimir/Loki/Tempo + Perses) and auto-wires each app into it (dashboards, SLOs, alerts) — no hand-rolled collector YAML, applied directly via kubectl/helm/HTTP, no GitOps controller in the path.
STATE: `pyproject.toml` version `0.2.1`; git tags `v0.1.0` ("the first end-to-end Phase-1 milestone", docs/versioning.md) and `v0.2.0` (2026-10-12, HEAD of the release). README, ROADMAP and docs/design.md say Phase 1 is complete (released as v0.1.0) and Phase 2 is current. The step-engine consumer (steps.py) and the job-mode/RBAC/tenant-resolution machinery shipped in v0.2.0 (CHANGELOG `[0.2.0]`). docs/design.md is a design plan, not a description of current capability: verify against code.
STACK: Python, CPython 3.14 exactly (`requires-python = ">=3.14,<3.15"` in pyproject.toml — not merely 3.14+); `uv` for deps/lock, `ruff` for lint/format. Runtime deps are only `pydantic==2.14.1` and `pyyaml==6.0.3` (pinned exactly, mirrored 1:1 into the Dockerfile's `pip install` — tests/unit/test_dockerfile_pins.py fails if they drift). Installed for dev via `uv sync`; run via `noto` (`noto.cli:main`) or `python -m noto.cli` (the container entrypoint). Shells out to `kubectl`, `helm`, and the pinned `sloth` binary; speaks plain HTTP (urllib, no client lib) to Perses and Mimir's ruler.
ENTRY:
- CLI `noto` → agent/noto/cli.py:main — subcommands `render` (artifacts to disk, touches nothing), `platform` (stand up the solo platform), `observe` (wire one gojira app in), `rules-sync`, `cardinality`, `feedback` (diagnostic-only, `--dry-run` required)
- Container image (Dockerfile, ENTRYPOINT `python -m noto.cli`, CMD `observe`): the one-shot in-cluster Job a provisioner (gojira) launches; see the README's "Running observe as a Job" for the full contract
SEAMS → card:
- step-engine     agent/noto/engine/engine.py, agent/noto/engine/ledger.py  (idempotent check→apply→record over a SQLite ledger; every provisioning step in the repo implements this)  → docs/arch/step-engine.md
- platform-record agent/noto/steps.py, agent/noto/rendering/rbac.py  (the `noto-platform-info` ConfigMap: born/tenant/environment, and the write-tenant/read-tenant resolution every read command performs)  → docs/arch/platform-record.md
- gojira-contract agent/noto/gojira/reader.py, agent/noto/job.py  (parses gojira.yaml operator-side and the job-mode env-var contract with a provisioner; emits the `ARGUS_SUMMARY` line back)  → docs/arch/gojira-contract.md
- profiles        agent/noto/profiles/models.py, agent/noto/profiles/loader.py, agent/noto/profiles/resolve.py  (baseline + class + override → the frozen ResolvedProfile every renderer consumes)  → docs/arch/profiles.md
- ruler-sync      agent/noto/feedback/ruler.py, agent/noto/steps.py (SyncRules)  (push-then-prune of rendered PrometheusRule groups into Mimir's ruler, the only thing that evaluates them)  → docs/arch/ruler-sync.md
- (uncarded) agent/noto/rendering/{collectors,alerts,slo,scrape,ottl,perses}.py — pure ResolvedProfile+Context → CRD/Sloth-spec/Perses-document render functions, golden-file contract-tested (tests/contract/golden/)
- (uncarded) agent/noto/perses_client.py — minimal urllib client (POST, fall back to PUT on 409) the ruler-sync-adjacent `ProvisionPerses` step is built on; Perses objects are HTTP API resources, never kubectl-applied
- (uncarded) agent/noto/integrations/{catalog.py,render.py} — `integration.yaml` → `receiver_creator`/`k8s_observer` config; the seed of the Phase-2 `noto-integrations` catalog design.md describes
- (uncarded) agent/noto/feedback/{mimir.py,distill.py,cardinality.py,models.py} — diagnostic usage-evidence path only (`noto feedback --dry-run`); `models.py`'s `ResourceUsage` mirrors gojira's `UsageProfile` wire shape via a golden fixture shared between the two repos (tests/unit/fixtures/feedback/usage_profile.json), but noto no longer POSTs it — gojira-sizing-agent is the sole production evidence producer (design.md decision, issue #52)

DEPS: reads gojira's `gojira.yaml` contract directly (gojira-contract seam) — the only sibling repo noto's code actually touches. techne / liminal / cabal / daedalus / sero are documented future integration points (CLAUDE.md, docs/design.md) with **no code yet** — verified: no import of any of the five anywhere under agent/noto/. Noto runs fully self-contained today; don't assume wiring to those repos exists.
HEALTH: unit tests (tests/unit/, plain `pytest`) plus contract/golden-file tests (tests/contract/, `-m contract`) pinning the enablement-guide's rendering opinions. CI (.github/workflows/ci.yml) on every PR and push to main: conventions lint, unit+contract, rendered-output validated against the REAL consumer tools (otelcol validate, sloth generate, kubeconform, percli — scripts/validate-rendered.sh), OpenTofu fmt+validate, Helm chart template check. `distro.yml` (ocb build + validate) is path-filtered to distro/rendering changes; `smoke.yml` (full kind-cluster Phase-1 DoD) is gated to `workflow_dispatch`/release only, ~15 min, never per-PR. Every job runs on a GitHub-hosted runner, and the last job in ci.yml, `ci`, needs all the others: it is the one check the branch rules require, with `dco` (tests/unit/test_ci_workflows.py).
GOTCHAS: `steps.py` (both `HelmInstall.check` and `_read_record`) uses PEP 758's parenthesis-free multi-exception `except json.JSONDecodeError, AttributeError:` — valid ONLY because pyproject.toml pins CPython to exactly `3.14.*`; run tests with `uv run pytest`/`uv run python`, never a system `python3`, or this reads as a SyntaxError. `noto feedback` is diagnostic-only and requires `--dry-run` — it is NOT the production rightsizing path (that's gojira-sizing-agent). The collector tier (agent/gateway/target-allocator) is rendered ONCE per cluster by `noto platform` from the platform profile, never per-app by `observe` — per-app/per-class drop rules do not reach the shared gateway (a registered, accepted gap, not a bug). `observe` never deletes a Kubernetes object it applied; a class change or app rename leaves stale ServiceMonitors/PodMonitors/PrometheusRules live until removed by label selector (README, "observe never deletes"). It does issue DELETEs to Mimir's ruler: the `SyncRules` step prunes the groups the ruler holds that this run did not render.
