# argus — repo card

WHAT: the observability arm of gojira. Reads a gojira-managed cluster's deployed apps and their workload class, then stands up an OSS observability platform (OTel Collector + Mimir/Loki/Tempo + Perses) and auto-wires each app into it (dashboards, SLOs, alerts) — no hand-rolled collector YAML, applied directly via kubectl/helm/HTTP, no GitOps controller in the path.
STATE: `pyproject.toml` version `0.1.0.dev0`; one git tag `v0.1.0` ("the first end-to-end Phase-1 milestone", docs/versioning.md). README, ROADMAP and docs/design.md say Phase 1 is complete (released as v0.1.0) and Phase 2 is current. The step-engine consumer (steps.py), the job-mode/RBAC/tenant-resolution machinery, and the `[Unreleased]` CHANGELOG entries sit on top of the tagged v0.1.0. docs/design.md is a design plan, not a description of current capability: verify against code.
STACK: Python, CPython 3.14 exactly (`requires-python = ">=3.14,<3.15"` in pyproject.toml — not merely 3.14+); `uv` for deps/lock, `ruff` for lint/format. Runtime deps are only `pydantic==2.13.4` and `pyyaml==6.0.3` (pinned exactly, mirrored 1:1 into the Dockerfile's `pip install` — tests/unit/test_dockerfile_pins.py fails if they drift). Installed for dev via `uv sync`; run via `argus` (`argus.cli:main`) or `python -m argus.cli` (the container entrypoint). Shells out to `kubectl`, `helm`, and the pinned `sloth` binary; speaks plain HTTP (urllib, no client lib) to Perses and Mimir's ruler.
ENTRY:
- CLI `argus` → agent/argus/cli.py:main — subcommands `render` (artifacts to disk, touches nothing), `platform` (stand up the solo platform), `observe` (wire one gojira app in), `rules-sync`, `cardinality`, `feedback` (diagnostic-only, `--dry-run` required)
- Container image (Dockerfile, ENTRYPOINT `python -m argus.cli`, CMD `observe`): the one-shot in-cluster Job a provisioner (gojira) launches; see the README's "Running observe as a Job" for the full contract
SEAMS → card:
- step-engine     agent/argus/engine/engine.py, agent/argus/engine/ledger.py  (idempotent check→apply→record over a SQLite ledger; every provisioning step in the repo implements this)  → docs/arch/step-engine.md
- platform-record agent/argus/steps.py, agent/argus/rendering/rbac.py  (the `argus-platform-info` ConfigMap: born/tenant/environment, and the write-tenant/read-tenant resolution every read command performs)  → docs/arch/platform-record.md
- gojira-contract agent/argus/gojira/reader.py, agent/argus/job.py  (parses gojira.yaml operator-side and the job-mode env-var contract with a provisioner; emits the `ARGUS_SUMMARY` line back)  → docs/arch/gojira-contract.md
- profiles        agent/argus/profiles/models.py, agent/argus/profiles/loader.py, agent/argus/profiles/resolve.py  (baseline + class + override → the frozen ResolvedProfile every renderer consumes)  → docs/arch/profiles.md
- ruler-sync      agent/argus/feedback/ruler.py, agent/argus/steps.py (SyncRules)  (push-then-prune of rendered PrometheusRule groups into Mimir's ruler, the only thing that evaluates them)  → docs/arch/ruler-sync.md
- (uncarded) agent/argus/rendering/{collectors,alerts,slo,scrape,ottl,perses}.py — pure ResolvedProfile+Context → CRD/Sloth-spec/Perses-document render functions, golden-file contract-tested (tests/contract/golden/)
- (uncarded) agent/argus/perses_client.py — minimal urllib client (POST, fall back to PUT on 409) the ruler-sync-adjacent `ProvisionPerses` step is built on; Perses objects are HTTP API resources, never kubectl-applied
- (uncarded) agent/argus/integrations/{catalog.py,render.py} — `integration.yaml` → `receiver_creator`/`k8s_observer` config; the seed of the Phase-2 `argus-integrations` catalog design.md describes
- (uncarded) agent/argus/feedback/{mimir.py,distill.py,cardinality.py,models.py} — diagnostic usage-evidence path only (`argus feedback --dry-run`); `models.py`'s `ResourceUsage` mirrors gojira's `UsageProfile` wire shape via a golden fixture shared between the two repos (tests/unit/fixtures/feedback/usage_profile.json), but argus no longer POSTs it — gojira-sizing-agent is the sole production evidence producer (design.md decision, issue #52)

DEPS: reads gojira's `gojira.yaml` contract directly (gojira-contract seam) — the only sibling repo argus's code actually touches. techne / liminal / cabal / daedalus / ladon are documented future integration points (CLAUDE.md, docs/design.md) with **no code yet** — verified: no import of any of the five anywhere under agent/argus/. Argus runs fully self-contained today; don't assume wiring to those repos exists.
HEALTH: unit tests (tests/unit/, plain `pytest`) plus contract/golden-file tests (tests/contract/, `-m contract`) pinning the enablement-guide's rendering opinions. CI (.github/workflows/ci.yml) on every PR and push to main: conventions lint, unit+contract, rendered-output validated against the REAL consumer tools (otelcol validate, sloth generate, kubeconform, percli — scripts/validate-rendered.sh), OpenTofu fmt+validate, Helm chart template check. `distro.yml` (ocb build + validate) is path-filtered to distro/rendering changes; `smoke.yml` (full kind-cluster Phase-1 DoD) is gated to `workflow_dispatch`/release only, ~15 min, never per-PR. tenishai repos carry no branch protection — CI reports, never blocks a merge.
GOTCHAS: `steps.py` (both `HelmInstall.check` and `_read_record`) uses PEP 758's parenthesis-free multi-exception `except json.JSONDecodeError, AttributeError:` — valid ONLY because pyproject.toml pins CPython to exactly `3.14.*`; run tests with `uv run pytest`/`uv run python`, never a system `python3`, or this reads as a SyntaxError. `argus feedback` is diagnostic-only and requires `--dry-run` — it is NOT the production rightsizing path (that's gojira-sizing-agent). The collector tier (agent/gateway/target-allocator) is rendered ONCE per cluster by `argus platform` from the platform profile, never per-app by `observe` — per-app/per-class drop rules do not reach the shared gateway (a registered, accepted gap, not a bug). `observe` never deletes a Kubernetes object it applied; a class change or app rename leaves stale ServiceMonitors/PodMonitors/PrometheusRules live until removed by label selector (README, "observe never deletes"). It does issue DELETEs to Mimir's ruler: the `SyncRules` step prunes the groups the ruler holds that this run did not render.
